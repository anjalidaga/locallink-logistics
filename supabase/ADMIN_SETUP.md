# Supabase setup for LocalLink Logistics

## 1. Apply the database migration

1. Open your Supabase project.
2. Open **SQL Editor** -> **New query**.
3. Paste and run `supabase/migration_locallink.sql`.
4. Confirm it finishes without an error. It adds `product_type`, `weight_grams`, `order_value`, and `location`, plus the extra fields needed by the existing booking form. It does not delete your existing tables or orders.

## 2. Deploy the Edge Function

The website sends public booking, tracking, and enquiry requests through the `locallink-api` Edge Function. Do not put the service-role key in the website.

With the Supabase CLI installed and logged in, run from the project folder:

```bash
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy locallink-api
```

Supabase provides `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` to deployed functions. If your project requires manual function secrets, set those values in **Edge Functions -> Secrets**. Never add the service-role key to `.env` or commit it to GitHub.

## 3. Configure the frontend

1. Copy `.env.example` to a file named `.env` in the project root.
2. In Supabase, open **Project Settings -> API**.
3. Copy the Project URL to `VITE_SUPABASE_URL`.
4. Copy the publishable/anon key to `VITE_SUPABASE_ANON_KEY`.
5. Save the file, then restart the local server (`npm run dev`).

The publishable/anon key is intended for the frontend. The service-role key is not.

## 4. Create an administrator account

1. In Supabase, open **Authentication -> Users** and create a user with an email and password.
2. Copy that user's UUID.
3. In SQL Editor, run the following, replacing the UUID with the actual user UUID:

```sql
insert into public.profiles (user_id, role)
values ('PASTE-ADMIN-USER-UUID-HERE', 'admin')
on conflict (user_id) do update set role = 'admin';
```

Use that email and password in the **Operations dashboard -> Database connection** sign-in form. Only a user whose `profiles.role` is `admin` can load the database order list or change database order statuses.

## 5. How the website maps to the database

| Website field | Supabase column |
| --- | --- |
| Order ID | `order_id` (generated by the API, e.g. `ORD...`) |
| Customer name | `customer_name` |
| Product type | `product_type` |
| Product weight in grams | `weight_grams` |
| Product value in rupees | `order_value` |
| Shipment status | `status` |
| Current destination/location | `location` |
| Pickup address | `pickup_address` |
| Delivery address | `delivery_address` |
| Delivery fee estimate | `delivery_charge` |
| Package quantity | `package_count` |
| Delivery service | `service_type` |

The delivery fee estimate and product value are separate fields. Tracking database orders requires both the Order ID and the phone number used for booking. No live GPS, payment processing, or email sending is implemented.

## Troubleshooting

- **Function not found / 404:** deploy `locallink-api` and check the function name.
- **Database column missing:** rerun the migration and inspect the exact SQL error.
- **Admin sign-in succeeds but says not authorised:** check the user's UUID in `public.profiles` and make sure `role` is `admin`.
- **CORS error:** the current Edge Function allows browser requests from any origin for this student demo. For a production deployment, restrict `Access-Control-Allow-Origin` to the exact website domain.
